## 1. VISION

Revenue generation is not the destination. Revenue is fuel.

The long-term objective is the development of an open, ethical, modular human–technology ecosystem centered on a handheld platform that evolves into a distributed network of intelligent health, sensing, communication, and research nodes.

The initial physical platform is an ENDS-derived modular handheld device. The platform is not viewed as a consumer product. It is viewed as an **evolving systems interface**.

Eventually the device becomes:
- sensing platform
- health monitoring platform
- computation node
- communications node
- research platform
- modular expansion platform
- edge AI platform
- distributed mesh participant

The hardware should evolve alongside software rather than becoming obsolete.

**Build for decades. Not versions.**

---

## 2. MISSION

Create a **knowledge operating system** — not merely an AI operating system.

AI models will come and go. Hardware will change. Protocols will evolve.

What remains is the **shared, versioned understanding** of missions, evidence, decisions, capabilities, and relationships.

If we succeed at that layer, QuillyOS won't depend on any single model, repository, or hardware platform. It becomes a durable framework that can incorporate future advances without losing continuity.

---

## 3. CORE PRINCIPLES

### 3.1 Rejection of Planned Obsolescence
- continuous augmentation
- continuous modularity
- continuous compatibility
- continuous adaptation

Every generation should enhance previous generations whenever possible. Software must preserve compatibility with older hardware. Hardware must expose modular interfaces. Knowledge must outlive software. Protocols must outlive hardware.

### 3.2 Protocol Over Platform
Rather than passing conversations between AI systems, every participant communicates through a common protocol. This protocol provides a structured representation of reality that survives model, repository, and hardware changes.

### 3.3 Shared Understanding Over Shared Memory
Instead of sharing thousands of chat messages, every agent receives the same structured context and produces structured outputs. Shared understanding replaces shared memory.

### 3.4 Human Agency First
The architecture optimizes for:
- human agency
- modularity
- repairability
- transparency
- privacy
- interoperability
- scientific integrity
- continuous learning

The objective is not replacing humans. The objective is augmenting human capability.

### 3.5 Nothing Duplicates Doctrine
Everything points upward. The `quillyos-foundation` repository contains truth. Everything else references it. No repository duplicates doctrine.

### 3.6 The Hub Becomes the Protocol
The steward remains human. The system itself becomes the coordination layer. This subtle distinction is what allows the architecture to survive decades.

## 4. ONTOLOGY

Everything should eventually be represented as one of the canonical object types. This becomes the universal language that every AI, every repo, and every hardware node understands.

### Canonical Object Types (15)

1. **Mission** — Why something exists
2. **Vision** — What the future looks like
3. **Goal** — A measurable target
4. **Project** — A bounded effort with deliverables
5. **Capability** — Something the system can do
6. **Skill** — A deployable, versioned capability
7. **Workflow** — An orchestrated sequence of operations
8. **Repository** — A versioned knowledge container
9. **Knowledge** — Validated, canonical understanding
10. **Evidence** — Observations, data, or experimental results
11. **Decision** — A recorded choice with rationale
12. **Proposal** — A suggested change awaiting review
13. **Node** — A physical or logical execution unit
14. **Protocol** — A defined communication or operation standard
15. **Relationship** — A typed connection between objects

Every artifact produced by any agent should map to one or more of these types.

## 6. KNOWLEDGE LIFECYCLE

Every document belongs to one or more lifecycles. Git is not merely version control. It becomes the **memory of QuillyOS**.

```
Capture
    ↓
Normalize
    ↓
Cross Reference
    ↓
Discussion
    ↓
Implementation
    ↓
Validation
    ↓
Archived Knowledge
```

### Stages

**Capture** — Ingest from any source: phone, conversation, document, sensor, market data.

**Normalize** — Convert to canonical format (Markdown/YAML). Extract entities. Summarize.

**Cross Reference** — Link to existing knowledge. Identify contradictions. Build relationships.

**Discussion** — Agent review, human review, consensus building.

**Implementation** — Code, workflow, hardware change, or operational procedure.

**Validation** — Test against evidence. Verify against reality. Record results.

**Archived Knowledge** — Promote to canonical status. Version. Index. Make retrievable.

### The Ingestion Pipeline

For automated ingestion (PicoClaw `/ingest`):

```
Import
    ↓
Deduplicate
    ↓
Convert
    ↓
Summarize
    ↓
Classify
    ↓
Cross Reference
    ↓
Knowledge Graph
    ↓
Git Repository
    ↓
Indexed Search
    ↓
Agent Context Package
```

No document should exist without context.

## 7. DECISION LIFECYCLE

How an idea graduates:

```
Observation
    ↓
Hypothesis
    ↓
Proposal
    ↓
Discussion
    ↓
Experiment
    ↓
Evidence
    ↓
Implementation
    ↓
Validation
    ↓
Canonical Knowledge
    ↓
Skill
    ↓
Automation
    ↓
Protocol
```

This is how QuillyOS evolves without becoming chaotic.

### Stage Definitions

- **Observation** — Something noticed in reality, markets, hardware, or systems
- **Hypothesis** — A testable explanation
- **Proposal** — A formal suggestion for change, documented in the Nexus Protocol format
- **Discussion** — Review by relevant agents and human steward
- **Experiment** — Controlled test to validate or invalidate
- **Evidence** — Recorded results, data, observations from experiment
- **Implementation** — The actual change: code, hardware, workflow, or operation
- **Validation** — Verification that implementation produces expected outcomes
- **Canonical Knowledge** — Accepted truth, versioned, cross-referenced
- **Skill** — A deployable capability derived from canonical knowledge
- **Automation** — A skill that runs without human intervention
- **Protocol** — A stabilized automation that becomes standard operating procedure

## 8. PROTOCOL PHILOSOPHY

### The Nexus Protocol

The purpose isn't to make GPT, Kimi, Manus, or PicoClaw agree. It's to give them a **shared representation** of the problem.

### Conceptual Flow

```
Reality
    ↓
Observation
    ↓
Evidence
    ↓
Structured Context (Context Matrix)
    ↓
Agent Translation Layer
    ↓
Agent-Specific Reasoning
    ↓
Proposal
    ↓
Consensus / Human Review
    ↓
Execution
    ↓
Knowledge Base Update
```

### Simplex Unification Format

Every participant receives identical structured context:

```yaml
mission: "What we are trying to accomplish"
current_architecture: "How the system is currently structured"
known_evidence: "What we have validated"
open_questions: "What remains unknown"
constraints: "What limits our options"
dependencies: "What we rely on"
objectives: "What success looks like"
current_milestones: "What we are working on now"
```

Instead of sharing conversations, agents share structured context. Every agent can parse this regardless of its reasoning style.

### The Four Layers

```
Layer 0 — Human Intent
    ↓
Layer 1 — Nexus Protocol
    ↓
Layer 2 — Knowledge / Reasoning / Memory
    ↓
Layer 3 — Execution Nodes (PicoClaw, Kimi, GPT, Manus, n8n, Pi Cluster)
    ↓
Layer 4 — Reality (Hardware, Markets, People, Sensors)
```

**Layer 0 (Human Intent):** The steward defines direction, ethics, and boundaries.

**Layer 1 (Nexus Protocol):** The translation layer that makes human intent machine-interpretable and model-agnostic.

**Layer 2 (Knowledge/Reasoning/Memory):** The structured, versioned, searchable understanding layer.

**Layer 3 (Execution Nodes):** Agents, workflows, hardware nodes that act on the knowledge layer.

**Layer 4 (Reality):** The physical world — hardware, markets, people, sensors — that feeds back into Layer 0.

## 10. EVOLUTION RULES

1. **Protocol stability over implementation churn.** The protocol should survive model, hardware, and repository changes.

2. **Evidence before doctrine.** No claim enters canonical knowledge without validation.

3. **Modularity at every layer.** Any component should be replaceable without redesigning the whole.

4. **Upward reference only.** Lower repositories reference higher ones. Never the reverse.

5. **Version everything.** Every document, every decision, every skill has a version.

6. **Human steward at Layer 0.** No automated system may override ethical boundaries or the steward's intent.

7. **Continuous migration, not replacement.** New capabilities augment old ones. Old capabilities are deprecated, not deleted, until fully superseded.

8. **Clone the repo, become a node.** Anyone who clones the public skills repository and runs the system becomes a spoke in the collective mesh.
