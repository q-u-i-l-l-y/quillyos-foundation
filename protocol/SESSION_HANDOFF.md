# SESSION HANDOFF MECHANISM
## Nexus Protocol v1.0

---

## PURPOSE

Enable seamless continuity between sessions across different agents (Kimi, GPT, PicoClaw, etc.). When a session ends, a structured brief is generated and pushed to Git. When a new session begins, the brief is pulled and ingested as context.

**Principle:** No session should start from zero context. The handoff brief is the bridge between sessions.

---

## HANDOFF BRIEF FORMAT

Every session handoff is a Markdown file in `session_briefs/` with the following structure:

```markdown
# SESSION BRIEF — [Agent Name] — [Date]
## Session ID: [uuid]
## Status: [complete | interrupted | ongoing]

---

## 1. SESSION CONTEXT

**Agent:** [Which agent ran this session]
**Date Started:** [ISO timestamp]
**Date Ended:** [ISO timestamp]
**Duration:** [Human-readable duration]
**Platform:** [Termux | Web | Desktop | Mobile]

---

## 2. MISSION CONTEXT

**Active Mission:** [Reference to mission ID]
**Context Matrix:** [Reference to active context matrix]
**North Star Alignment:** [Which long-term vision this serves]

---

## 3. WHAT WAS DONE

### Completed
- [ ] Task description → [artifact link or result]
- [ ] Task description → [artifact link or result]

### In Progress
- [ ] Task description → [current state, blockers, next step]
- [ ] Task description → [current state, blockers, next step]

### Blocked
- [ ] Task description → [why blocked, what is needed]

---

## 4. DECISIONS MADE

| Decision | Rationale | Reversibility | Status |
|----------|-----------|---------------|--------|
| [Description] | [Why] | [reversible / irreversible] | [approved / pending] |

---

## 5. KNOWLEDGE GENERATED

### New Artifacts
- [Artifact type] → [Path or description]
- [Artifact type] → [Path or description]

### Updated Knowledge
- [Knowledge ID] → [What changed]

### Open Questions Raised
- [Question] → [Why it matters]

---

## 6. AGENT STATE

### Context Loaded
- [List of context matrices active during session]

### Skills Used
- [List of skills invoked]

### Workflows Triggered
- [List of workflows executed or modified]

---

## 7. NEXT SESSION PREP

### Recommended Next Actions
1. [Action] — [Why this is priority]
2. [Action] — [Why this is priority]

### Context to Load
- [Context Matrix IDs to activate]
- [Agent roles to invoke]

### Warnings / Notes
- [Anything the next agent should know]

---

## 8. EVIDENCE & REFERENCES

### Git Commits
- [commit hash] — [Description]

### Files Modified
- [Path] — [What changed]

### External References
- [Link or reference]

---

*Generated by [agent] at [timestamp]*
*Next session: pull this brief and continue*
```

---

## WORKFLOW

### Ending a Session (Push)

1. **Agent generates brief** — Compile session state into the handoff format above.
2. **Write to `session_briefs/`** — Filename: `YYYY-MM-DD_HH-MM-[agent]-[brief-id].md`
3. **Update `session_briefs/LATEST.md`** — Symlink or copy of the most recent brief
4. **Commit and push** — `git add session_briefs/ && git commit -m "session handoff: [brief-id]" && git push`
5. **Notify** — If applicable, notify the steward or next agent

### Starting a Session (Pull)

1. **Pull latest** — `git pull origin main`
2. **Read `session_briefs/LATEST.md`** — Get the most recent brief
3. **Ingest context** — Load referenced context matrices, skills, and workflows
4. **Confirm understanding** — Agent summarizes what it understands from the brief
5. **Continue** — Proceed with recommended next actions

---

## AUTOMATION

### For Termux / PicoClaw

Use `scripts/handoff.sh` to pull the latest brief:
```bash
./scripts/handoff.sh
```

Use `scripts/push_brief.sh` to push a session brief:
```bash
./scripts/push_brief.sh "Session summary text"
```

### For Web Agents (Kimi, GPT)

1. Agent generates brief at session end
2. User copies brief and pushes via GitHub web interface or Termux
3. Next session: user pulls brief and pastes as opening context

**Future:** Direct GitHub API integration for web agents.

```
YYYY-MM-DD_HH-MM-[agent-role]-[brief-id].md

2026-07-08_16-00-picoclaw-ingestion-002.md
2026-07-08_18-45-gpt-research-003.md
```

---

## BRIEF LIFECYCLE

```
Session Active
    ↓
Brief Generated (end of session)
    ↓
Pushed to session_briefs/
    ↓
Next Session Pulls Brief
    ↓
Brief Ingested as Context
    ↓
Brief Archived (after 30 days or 10 newer briefs)
    ↓
Brief Summarized into Knowledge Graph
    ↓
Brief Removed from session_briefs/ (preserved in Git history)
```

## INTEGRATION WITH NEXUS PROTOCOL

The handoff brief is a specialized Context Matrix. It maps to:

- **Object Type:** `Knowledge` (session state)
- **Relationships:**
  - `produces` → Artifacts created
  - `depends_on` → Context matrices loaded
  - `enables` → Next session
  - `part_of` → Mission

Every brief should reference the active Mission and Context Matrix IDs.
